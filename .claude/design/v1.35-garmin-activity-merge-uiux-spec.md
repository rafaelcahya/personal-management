# Garmin Activity Merge: UI/UX Spec (#922)

Module: Running. Release folder: v1.35. PRD: `.claude/prd/running/garmin-integration.md` section 26. API contract: Postman folder "Running > Garmin merge (#922, planned)".

## 1. Overview and scope

Strava stays the base. Garmin adds extra numbers. The app never calls Garmin on page load, so every screen reads our own DB.

In scope:

- Settings: Garmin connection card.
- Activity detail: Running Form, Training Effect, "From Garmin" RPE hint, per-activity Refresh.
- Activities list: Training Effect badge and Garmin indicator.
- Dashboard sync status bar: Garmin segment.

Out of scope: trend charts, AI coach changes, sleep/HRV, push or in-app expiry notifications, UI for training load / recovery HR / lactate threshold HR, and `feel` (the 0-100 scale is not defined in the PRD, so hide it).

Base components used (all exist in `components/base/`, none need changes): Card, Field family, PasswordInput, Input, Button, Banner, Modal, Skeleton, Collapsible, Badge, Tooltip. Frontend must confirm: (a) a date field. A `DatePicker` folder only has `calendarParts.jsx`, so if there is no ready component, use `Input type="date"` inside a `Field`. (b) Whether `PageHeader` has an actions slot (needed for Refresh).

## 2. Settings: Garmin connection card

File: `app/main/running/(app)/settings/components/GarminSection.jsx`, rendered right under `StravaSection`. Same shell as Strava: `Card as="section"`, `CardHeader` with `CardIcon` (lucide `Watch`), title "Garmin", description "Add your Garmin API key to enrich runs with extra watch data". `CardContent className="p-0"`, rows split by `divide-y divide-slate-100`, `px-5 py-4`.

Accent: no Garmin brand token exists. Primary buttons use `bg-sky-700 hover:bg-sky-800 text-white focus-visible:ring-2 focus-visible:ring-sky-300 h-11 md:h-8`. Code comment: "No Garmin brand token; sky-700 keeps white text at AA contrast". Reuse `SectionLoadError` for load errors.

### 2.1 Async states of the status load (GET /garmin/connection)

| State   | Look                                                                                                            |
| ------- | --------------------------------------------------------------------------------------------------------------- |
| Loading | `garminConnectionLoading_settings`: Skeleton `h-4 w-40` + Skeleton `h-3 max-w-64`, same shape as the Strava one |
| Error   | `SectionLoadError` with message and Retry (`garminRetryBtn_settings`)                                           |
| Success | One of the 4 connection states below                                                                            |
| Empty   | Is the `not_connected` state (it has a CTA: the form)                                                           |

### 2.2 Connection states

**not_connected** (`garminNotConnectedState_settings`)

- Title "Not connected" (`text-sm font-medium text-slate-800`). Helper (`text-xs text-slate-400`): "In Garmin Connect, create a Personal API key, then paste it here. Pick the same expiry date you chose there."
- Form (see 2.3) and `Connect` button (Link2 icon).

**connected** (`garminConnectedState_settings`)

- Row 1: green Badge "Connected" (`bg-green-50 text-green-700 border-green-200`), then `garminKeyLast4Text_settings`: "Key ending •••• a2e9" (`tabular-nums`).
- `garminExpiryText_settings`: "Expires in N days" (`text-xs text-slate-400`), with the date, for example "Expires in 365 days (24 Oct 2027)". Singular: "1 day". Today: "Expires today".
- `garminLastSyncedText_settings`: "Last synced: 24 Oct 2026, 02:00" (same `toLocaleString` format as Strava). Null shows "Never synced".
- Actions (right side on `sm`, stacked full width on mobile): `Replace key` (outline, opens a Modal with the form), `Remove` (outline red like Strava Disconnect, LogOut icon).
- Expiry warning (N <= 14): `Banner variant="warning"` (or the same amber block Strava uses), id `garminExpiryWarning_settings`, `role="status"`, AlertTriangle icon. Copy: "Expires in N days. Make a new key in Garmin Connect." At 0 days: "Expires today. Make a new key in Garmin Connect." Classes: `bg-amber-50 border-amber-200 text-amber-800`, icon `text-amber-600`. The meaning is carried by the icon and text, never color alone. N > 14 shows no banner and no amber.
- Below: the Sync block (2.4).

**expired** (`garminExpiredState_settings`)

- Amber block: title "Your key expired", text "Garmin data stopped coming in. Strava still syncs as normal. Save a new key to catch up on missed runs." Then the form (2.3) with button label "Save new key".
- Ghost `Remove` link stays available.

**invalid** (`garminInvalidState_settings`)

- Red block (`bg-red-50 border-red-200 text-red-700`, AlertCircle), title "Garmin rejected your key". `garminLastErrorMsg_settings` shows `last_error` (fallback "Garmin could not accept this key."). Strava still syncs. Then the form and a ghost `Remove`.

### 2.3 Save / replace key form

react-hook-form + Zod (Frontend). Both fields use the form field styling standard: `text-sm font-medium focus-visible:ring-violet-200 focus-visible:border-violet-600 selection:bg-violet-500`. Required marker on both labels.

| Field       | Component                  | Id                              | Rules and copy                                                                                                                                                  |
| ----------- | -------------------------- | ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| API key     | `PasswordInput` in `Field` | `garminApiKeyInput_settings`    | Required. Label "API key". Placeholder "Paste your Garmin API key". `autoComplete="off"`. Error "Enter your Garmin API key"                                     |
| Expiry date | Date field in `Field`      | `garminExpiresAtInput_settings` | Required, today to today+1 year. Label "Key expiry date". Description "The date you picked in Garmin Connect". Error "Pick the expiry date you chose in Garmin" |

Submit button `garminConnectBtn_settings` (new key) or `garminSaveKeyBtn_settings` (in expired/invalid/replace Modal).

Button states:

- Default: sky-700.
- Hover: sky-800.
- Active: `active:bg-sky-900`.
- Focus: `ring-2 ring-sky-300`.
- Disabled while submitting, with a spinner and the label "Checking key…".

Server results:

- 200: toast "Garmin connected". The card flips to `connected`. If the old status was expired/invalid, or this is the first connect, show the info notice `garminCatchUpMsg_settings`: "Catching up on missed runs. New data will appear shortly."
- 400: inline `FieldError` under the key: "Garmin rejected the API key". The key field is cleared and refocused.
- 502: inline alert `garminSaveErrorMsg_settings` (`role="alert"`, red): "Garmin API is unavailable. Try again later." The key stays filled.
- Nothing is stored in either error case. Say that in the helper text only when it happens: "Nothing was saved."

Replace key opens a Modal `garminReplaceDialog_settings` (header icon + title "Replace Garmin key" + description, body is the form, footer Cancel `garminReplaceCancelBtn_settings` + Save). The Modal cannot be closed while submitting.

### 2.4 Sync block (connected state only)

Row: title "Sync Garmin Data", text "Link Garmin numbers to your runs and import runs that are missing. Defaults to the last 7 days." Button `garminSyncNowBtn_settings` "Sync Now" (RefreshCw icon, spins while loading, label "Syncing…", disabled while loading).

Collapsible `garminSyncRangeToggle_settings` "Choose dates (optional, max 90 days)". It holds `garminSyncFromInput_settings` and `garminSyncToInput_settings` (date fields, side by side from `sm`, stacked on mobile). Client validation: both set or both empty, From <= To, range <= 90 days, otherwise the error "Date range must be 90 days or less" (or "From must be before To") under the fields, and the button is disabled with that message as the reason (helper text, not a bare tooltip). The server also returns this error, so show the same text if it comes back.

| Result       | UI                                                                                                                                                                            |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 202          | Info notice `garminSyncNoticeMsg_settings` (`role="status"`, blue like Strava): "Sync started. New data will appear shortly." No count and no polling. Refetch status quietly |
| 429          | Same info notice style (not red): "A Garmin sync is already running."                                                                                                         |
| 409          | Refetch status, card flips to not_connected, red alert `garminSyncErrorMsg_settings`: "Garmin is not connected."                                                              |
| 400          | Inline range error as above                                                                                                                                                   |
| 502 or other | Red alert `garminSyncErrorMsg_settings` with the API message, fallback "Sync failed. Please try again."                                                                       |
| 401          | Existing app 401 handling                                                                                                                                                     |

### 2.5 Remove (destructive)

Modal `garminRemoveDialog_settings`, max-w-md. Title "Remove Garmin connection?". Description: "Your saved key will be deleted and syncing from Garmin will stop. Garmin data already added to your runs stays. You can add a key again at any time." Footer: Cancel `garminRemoveCancelBtn_settings` (ghost), Remove `garminRemoveConfirmBtn_settings` (`bg-red-600 hover:bg-red-700 text-white`, label "Removing…" while loading, both buttons disabled). Error `garminRemoveError_settings` (`role="alert"`) inside the Modal. Success: close, toast "Garmin connection removed", card shows not_connected.

## 3. Activity detail: Garmin sections

Page: `app/main/running/(app)/activities/[id]/page.jsx`. New components in `../components/`: `RunningFormSection.jsx`, `TrainingEffectSection.jsx`, `RefreshGarminButton.jsx`.

Order: after the Stats section and before `PerceivedEffortSection`. Use `SectionLabel` and `StatTile` from `activityShared`. Garmin data comes with the activity payload, so the sections have no skeleton of their own (the page skeleton covers them) and no error state of their own.

Hide rules (PRD 26.7):

- `garmin === null`: neither section renders. No empty card, no banner, no error.
- A tile with a null value is hidden.
- If every tile in a section is null, the whole section is hidden.
- `training_load`, `recovery_hr`, `lactate_threshold_hr`, `feel`: never rendered.

### 3.1 Running Form (`runningFormSection_activityDetailPage`)

`SectionLabel` "Running Form". Grid `grid grid-cols-2 sm:grid-cols-3 lg:grid-cols-6 gap-3`.

| Tile                 | Source field                     | Format                             | Id                                           |
| -------------------- | -------------------------------- | ---------------------------------- | -------------------------------------------- |
| Ground contact time  | `avg_ground_contact_time_ms`     | `255 ms`                           | `groundContactTile_activityDetailPage`       |
| Vertical oscillation | `avg_vertical_oscillation_cm`    | `8.1 cm`                           | `verticalOscillationTile_activityDetailPage` |
| Vertical ratio       | `avg_vertical_ratio_pct`         | `8.2 %`                            | `verticalRatioTile_activityDetailPage`       |
| Stride length        | `avg_stride_length_cm`           | `1.00 m` (cm / 100, 2 decimals)    | `strideLengthTile_activityDetailPage`        |
| Cadence              | `avg_run_cadence_spm`            | `172 spm` with caption "both legs" | `garminCadenceTile_activityDetailPage`       |
| Grade-adjusted pace  | `grade_adjusted_pace_sec_per_km` | `5:47 /km` via `fmtPace`           | `garminGapTile_activityDetailPage`           |

Values `tabular-nums`. The existing Strava cadence tile (`cadenceTile_activityDetailPage`, per leg) is unchanged. The Garmin tile sits only in this section, labeled "Cadence (spm, both legs)" so nobody compares 88 with 172 by mistake. Each tile has no hover or click behavior (display only), so only the info Tooltip trigger has focus states (see 3.4).

### 3.2 Training Effect (`trainingEffectSection_activityDetailPage`)

`SectionLabel` "Training Effect". Card body, two columns from `sm` (stacked on mobile):

- Aerobic (`aerobicTeMeter_activityDetailPage`) and Anaerobic (`anaerobicTeMeter_activityDetailPage`). Each shows: caption (`text-xs text-slate-400`), the large value `5.0` (`text-2xl font-semibold tabular-nums`), a 5-segment meter, and the message text (for example "Overreaching").
- Meter: 5 segments, `h-2 rounded-full`, filled up to the value (a fractional value fills the last segment partially via width %). The unfilled part is `bg-slate-100`. `role="img"` with `aria-label="Aerobic training effect 5.0 of 5, Overreaching"`.
- Label Badge `trainingEffectLabel_activityDetailPage` at the top of the section, long form (title case: "Lactate Threshold").
- Hide logic: a meter is hidden when its value is null. The label is hidden when null or `UNKNOWN`. The section is hidden when nothing remains.
- Body cost row (shown only when filled), using StatTile: `bodyBatteryTile_activityDetailPage` ("Body battery", `−21`, real minus sign) and `sweatLossTile_activityDetailPage` ("Sweat loss", `1.45 L`, or `850 ml` under 1000 ml).

Meter and value colors (Tailwind palette, no hex; text and meter use the same hue, text at 700, meter at 500):

| TE value  | Hue     | Meaning shown in text |
| --------- | ------- | --------------------- |
| under 1.0 | slate   | No benefit            |
| 1.0 - 1.9 | sky     | Minor                 |
| 2.0 - 2.9 | emerald | Maintaining           |
| 3.0 - 3.9 | violet  | Improving             |
| 4.0 - 4.9 | amber   | Highly improving      |
| 5.0       | red     | Overreaching          |

The message text always comes from the API message (`aerobic_te_message`, trailing number stripped, title-cased: `OVERREACHING_14` becomes "Overreaching", `NO_ANAEROBIC_BENEFIT_0` becomes "No anaerobic benefit"). The table's "Meaning" text is only the fallback when the message is missing. Color is never the only signal because the value and text are always visible.

### 3.3 RPE hint

In `PerceivedEffortSection`, when `data_sources.perceived_exertion_from === 'garmin'` and `rpe` is still the Garmin value: a chip `rpeGarminHint_activityDetailPage` next to the "Borg CR10" chip: `text-2xs bg-violet-50 text-violet-700 px-2 py-0.5 rounded-full font-medium`, text "From Garmin", with a Tooltip: "Filled from your watch. Pick a number to change it." The chip is `tabIndex=0` so the Tooltip opens on keyboard focus. Once the user picks a different value (or clears it), the chip is hidden locally. After a refetch the server value rules. No other change to the picker. The user's own value is never marked.

### 3.4 Refresh Garmin data (`refreshGarminBtn_activityDetailPage`)

Placement: page header actions (via `PageHeader`), not inside the sections, because the sections do not exist until the run is linked and that is exactly when the user needs this button. Shown only when Garmin connection status is `connected` (read from the connection endpoint or sync status). Hidden for not_connected, expired, invalid.

Button: ghost/outline, RefreshCw icon + "Refresh Garmin data" (icon only with `aria-label` below 375px-wide cases is not needed, text wraps in the actions slot; full width under `sm`).

| State          | Behavior                                                                          |
| -------------- | --------------------------------------------------------------------------------- |
| Default        | outline, violet focus ring                                                        |
| Hover / Active | slate-50 / slate-100                                                              |
| Loading        | icon spins, `aria-busy="true"`, disabled, label "Refreshing…"                     |
| Success (200)  | toast "Garmin data updated", then refetch the activity                            |
| 404            | toast (info) "No matching Garmin run found for this activity"                     |
| 409            | toast "Garmin is not connected", button hides                                     |
| 502            | error toast "Garmin API is unavailable. Try again later." (stays until dismissed) |

A tooltip on the info icon is not needed. Disabled reason: the loading label itself.

## 9. Accessibility

- Every field has a visible label. Errors use `FieldError` linked with `aria-describedby`. Key field has `autoComplete="off"`.
- Async messages: `role="status"` for info and success, `role="alert"` for errors.
- Expiry warning has an icon and text, not color alone.
- Modals trap focus (Radix), return focus to the trigger, and title and description are announced.
- TE meters use `role="img"` with a full `aria-label`.
- Focus order follows reading order. In the Settings card: status, actions, sync block, range toggle.
- Icons are `aria-hidden`. The Garmin indicator has sr-only text.
- The Refresh button sets `aria-busy` while loading and toasts are announced by Sonner.

## 12. Frontend handoff notes

- No base component changes are expected. Confirm the date field and `PageHeader` actions slot (see section 1). If either is missing, raise it as a Base Component Modification Request before building.
- Fetch functions go in `lib/api/running`. Refetch the activity after a successful refresh.
- After a connect, refetch status. Do not poll after Sync Now.
- Never put the key in state longer than the submit, in logs, or in the URL.
